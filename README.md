# 営業CRM（メール営業の管理システム）

小規模な営業チームが、問い合わせフォーム・メールでの新規営業を管理するための社内CRMです。
実際に業務で使っているシステムから、人名・社名・運用データを取り除いて公開しています。

**デモ：https://sales-crm-six-orpin.vercel.app**
「管理者としてログイン」を押すと、架空のデータで全機能を触れます（メール・カレンダーは実際には送られず、データは毎晩初期化されます）。

## できること

- **顧客管理**：CSVで最大3万件を取り込み、表記ゆれ（全角/半角・ひらがな/カタカナ・「株式会社」の有無）を吸収して重複を検出
- **メール送信**：Gmail API で個別送信・一括送信。テンプレートは担当者ごとに切り替え、送信履歴を商材別に記録
- **KPI管理**：月の目標契約数から「アポ数→送信数」の日次ノルマを逆算。未達分の繰り越し、祝日・開始日の考慮、アポ実績によるノルマの増減まで自動計算
- **分析**：担当者別・商材別の送信数／アポ数を集計（集計はDB側のRPCで実行）
- **業務委託スタッフ機能**：スタッフ専用ログインと専用画面。フォーム送信作業を取り合わないよう、案件を1件ずつ確保（claim）→記録→解放する作業キュー
- **アポ・タスク・メモ**：チーム内の予定共有（アポは Google カレンダーと同期）
- **外部連携API**：毎朝の日報（自動化ツール→チャット通知）用のトークン認証API

## 技術構成

| 分類 | 使用技術 |
|---|---|
| フロント／サーバー | Next.js 16（App Router）・React 19・TypeScript・Tailwind CSS 4 |
| 認証 | Auth.js（Google OAuth＋スタッフ用のID/パスワード）・ミドルウェアで役割ごとにアクセス制御 |
| DB | Supabase（PostgreSQL）・行単位の権限（RLS）・集計用のSQL関数（RPC） |
| 外部API | Gmail API・Google Calendar API |
| ホスティング | Vercel（東京リージョン） |
| テスト | Node.js 標準のテストランナー（`node:test`）・Supabaseの偽物（`test/fakeSupabase.ts`）で単体テスト |

## 設計で工夫した点

- **権限の多重化**：ミドルウェア（ページ単位）→ API ごとの `requireAdmin` / `requireAuth` / `requireWorker` → DB の RLS、の3段で守る。スタッフは許可したパス以外に入れない
- **KPIの繰り越し計算**：月をまたぐ未達分・アポ実績による調整・「一度減った繰越は戻さない」などの業務ルールを SQL 関数と TypeScript の両方で実装し、テストで固定（`src/lib/kpiCarry.ts`・`supabase-kpi-*.sql`）
- **表記ゆれの吸収**：検索・重複チェック用の正規化を関数に切り出してテスト（`src/lib/normalize*.ts`）
- **トークン比較の安全性**：合言葉・連携トークンは時間差の出ない比較で確認し、ログイン前の合言葉には回数制限を設定（`src/lib/safeEqual.ts`）
- **機能フラグ**：新機能は特定アカウントだけに先行公開し、設定画面から切り替えられる
- **チーム構成の一元化**：担当者の並び順・表示名・責任者を `src/config/team.ts` の1か所にまとめ、人の入れ替えはこのファイルだけで済む

## 動かし方

```bash
cp .env.example .env.local   # 値を入れる
npm install
npm run dev                  # http://localhost:3000
npm test                     # 単体テスト
npm run lint                 # 静的チェック
```

DB は Supabase に次の順で流します。

1. `supabase-schema.sql` → `supabase-schema-extra.sql`
2. そのほかの `supabase-*.sql`（`supabase-demo-settings.sql` はデモ用なので、デモを作るときだけ）
3. 最後に `supabase-rls.sql`

## デモ版

`NEXT_PUBLIC_DEMO_MODE=1` で起動すると、架空データで触れるデモになります（本番とは別の Supabase プロジェクトを使用）。

- **ワンクリックでログイン**：管理者・業務委託スタッフのどちらの画面でも入れる
- **外部送信なし**：メール送信・カレンダー登録は記録だけ残し、Google には送らない
- **毎晩初期化**：`/api/demo/reset` を Vercel Cron で実行し、架空の顧客360社・送信履歴・アポを作り直す（`src/lib/demoSeed.ts`）
- **設定画面がCMSになる**（管理者のみ）
  - 会社名・システム名・ロゴ・テーマカラー（7色）
  - 全画面に出すお知らせバナー
  - サイドバーのメニューの表示・非表示
  - 顧客一覧の列の表示・並び順
  - チーム（名前・メール・色・並び順・追加削除）・ステータス（名前・色・並び順）・月ごとのKPI目標
  - 商材・ジャンルの名前変更、メールテンプレートの差し込み変数とプレビュー

見た目の設定は `demo_settings` 表に JSON 1行で持ち、サーバー側で読んでから描画するので、読み込み時に色や名前がちらつきません（`src/lib/siteSettings*.ts`・`src/components/SiteSettingsProvider.tsx`）。テーマカラーは Tailwind 4 の CSS 変数（`--color-indigo-*`）を差し替えて全画面に効かせています。
